# دكة للتقنية — السيرفر وقاعدة البيانات

نظام حقيقي (Node.js + Express + قاعدة بيانات SQLite) لاستقبال طلبات العملاء من الموقع، مع لوحة تحكم محمية بكلمة مرور لإدارة الطلبات، بالإضافة إلى **لوحة أنظمة فعلية تشتغل** (نقاط بيع، مخزون، حضور وانصراف، عملاء، أمن ومراقبة، تخطيط موارد).

## 1. التشغيل على جهازك (اختياري، للتجربة قبل الرفع)

يتطلب [Node.js](https://nodejs.org) نسخة 18 أو أحدث.

```bash
cd dakka-backend
npm install
cp .env.example .env
npm start
```

افتح المتصفح على: `http://localhost:3000`

## 3. تشغيل الموقع فعلياً على الإنترنت (استضافة)

المشروع كودك، لكن يحتاج مكان يشتغل فيه 24 ساعة. أسهل خيارات مجانية/رخيصة تدعم Node.js:

- **Render.com** — اربط حساب GitHub، اختر المستودع، وسيكتشف `npm start` تلقائياً.
- **Railway.app** — نفس الفكرة، ربط مباشر بـ GitHub.

في كلا الخيارين، بعد الربط أضف متغيرات البيئة (Environment Variables) من إعدادات المشروع:
- `ADMIN_PASSWORD` = كلمة مرور قوية من اختيارك
- `PORT` = عادة تُضبط تلقائياً من الاستضافة

⚠️ **مهم:** غيّر `ADMIN_PASSWORD` قبل ما تنشر الموقع للعامة — الكلمة الافتراضية `dakka2026` معروفة الآن وما ينفع تتركها.

## هيكلة المشروع

```
dakka-backend/
├── server.js         # السيرفر الرئيسي (Express) — كل نقاط الوصول
├── db.js             # إعداد قاعدة البيانات (SQLite) — كل الجداول
├── public/
│   ├── index.html    # الموقع التسويقي + نموذج الطلبات + لوحة طلبات + فيديوهات
│   ├── systems.html   # لوحة الأنظمة الفعلية (نقاط بيع، مخزون، حضور، عملاء...)
│   └── style.css      # التنسيقات المشتركة بين الصفحتين
├── package.json
├── .env.example
└── .gitignore
```

## لوحة الأنظمة الفعلية

افتح `public/systems.html` (أو من زر "فتح لوحة الأنظمة" داخل لوحة التحكم بالموقع الرئيسي) — تسجّل دخول بنفس كلمة مرور الأدمن، وتلقى ست أنظمة فعلية متصلة بقاعدة البيانات:

| النظام | وش تسوي فيه |
|---|---|
| **نقاط البيع** | تختار منتج وكمية، تضيفه للسلة، وتتمّ البيع — يخصم تلقائياً من المخزون |
| **المخزون** | تضيف منتجات بسعر وكمية وحد تنبيه، وتتابع الكميات (شارة تحذير عند النقص) |
| **الحضور والانصراف** | تضيف موظفين، وتسجّل حضور/انصراف لكل واحد بضغطة، مع سجل بالوقت |
| **العملاء (CRM)** | تضيف عميل باسمه وجواله وملاحظات، وتشوف كل عملائك بقائمة واحدة |
| **الأمن والمراقبة** | سجل ملاحظات وأحداث (دخول غريب، عطل كاميرا...) بثلاث درجات خطورة |
| **تخطيط الموارد** | تسجّل إيرادات ومصروفات، ويحسب لك الصافي تلقائياً |

كل البيانات تُحفظ فعلياً في `dakka.db` (قاعدة بيانات SQLite حقيقية على السيرفر) — مو تخزين مؤقت.

⚠️ لم أقدر أشغّل السيرفر فعلياً واختبره في بيئتي الحالية (لا يوجد اتصال إنترنت لتثبيت الحزم عبر npm)، لكن راجعت الكود بعناية والتحقق من تطابق كل نقاط الوصول بين الواجهة والسيرفر. جرّبه أول شي على جهازك بالخطوات في القسم الأول من هذا الملف، وأخبرني لو طلعت أي مشكلة.

## إضافة فيديوهات الشرح

الموقع فيه قسم "فيديوهات الشرح" بتبويبات (نظرة عامة + فيديو لكل نظام)، ويعرضها مباشرة من يوتيوب (مافي رفع ملفات فيديو للسيرفر — يتجنب مشكلة حدود حجم الملفات في GitHub تماماً).

**الخطوات:**

1. ارفع كل فيديو على يوتيوب. لو ما تبي يظهر للعموم في قناتك، اختر وضع **"غير مُدرج" (Unlisted)** عند الرفع — يفتح فقط لمن يملك الرابط ولن يظهر في نتائج البحث أو قناتك العامة.
2. من رابط الفيديو، انسخ **المعرّف (ID)** — هو الجزء اللي بعد `v=`:
   - مثال: `https://www.youtube.com/watch?v=dQw4w9WgXcQ` → المعرّف هو `dQw4w9WgXcQ`
3. افتح `public/index.html`، ودوّر (Ctrl+F) على `VIDEO_IDS` بالقرب من نهاية الملف، وحط كل معرّف بمكانه:

```js
const VIDEO_IDS = {
  overview:   'dQw4w9WgXcQ', // فيديو نظرة عامة
  pos:        '',            // فيديو نقاط البيع
  inventory:  '',
  attendance: '',
  security:   '',
  erp:        '',
  crm:        ''
};
```

4. احفظ الملف. أي قسم تتركه فارغاً `''` يظهر تلقائياً برسالة "لم يُضف بعد" بدل ما يتعطل — تقدر تضيفهم بالتدريج.

## ملاحظات أمنية

- كلمة مرور الأدمن تُقارن مباشرة من متغير البيئة — لا تشاركها ولا ترفع ملف `.env` على GitHub (مستثنى تلقائياً عبر `.gitignore`).
- جلسات الدخول محفوظة في ذاكرة السيرفر؛ تُمسح عند إعادة تشغيله (يعني الأدمن يسجّل دخول من جديد بعد أي إعادة تشغيل).
- قاعدة البيانات ملف SQLite محلي (`dakka.db`) — للمشاريع الأكبر لاحقاً يمكن الترقية لقاعدة بيانات مثل PostgreSQL.
- شغّل الموقع دائماً عبر HTTPS عند نشره (الاستضافات المذكورة أعلاه توفر هذا تلقائياً).
